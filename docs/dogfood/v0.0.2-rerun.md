## Coordinator and credential workflow

1. `local-board actor coordinator --kind agent --role admin --json` wrote machine-readable bootstrap credentials directly to a mode-0600 ignored file.
2. MCP `create_actor` provisioned two members and one viewer.
3. Role-filtered `tools/list` returned 40 admin, 37 member, and 12 viewer tools.
4. A deliberate viewer mutation returned structured `forbidden`.
5. MCP `rotate_actor_token` replaced the web implementer's token; the previous token received HTTP 401, while the replacement authenticated with `whoami`.

The rotation behavior, separate attribution, and role catalogs establish the main v0.0.2 product gain: a coordinator can delegate and revoke access using public MCP rather than shell-only actor creation.

## Failures, friction, and corrections

- One stale transition was operator error: the client supplied revision 3 after context had reported revision 1, incorrectly assuming two checklist additions incremented revision. The server returned a correct structured conflict.
- A second stale transition was an intentional conflict probe after lifecycle operations had advanced the issue to revision 4.
- Protocol evidence confirmed that comments, checklist additions/updates, and Git links did not bump issue revision; transitions and claims did.
- Tool-domain failures use HTTP 200 with `result.isError=true`; clients must inspect the MCP result rather than HTTP status alone. Authentication failure correctly used HTTP 401.
- The core lifecycle remained chatty: 21 context reads and 14 transitions were observed.
- Members did not see actor administration, but still had broad project, release, milestone, workflow, and label mutation permissions.
- Startup lacked a machine-readable readiness signal. Ctrl-C produced a `KeyboardInterrupt` traceback and non-zero exit, reproducing the v0.0.1 runtime defect.
- Four `.pyc` files were accidentally committed by the evaluator after running tests and a broad `git add`. This consumer-project hygiene error was corrected with ignore rules and is not attributed to the Local Board package.

## Credential near-miss

No token entered board content, the report, or tracked Git files. However, the evaluator's first generic MCP logger wrote token-bearing `create_actor` responses into an ignored JSONL file. The evaluator detected this, recursively redacted token fields in existing evidence, updated the logger, and kept credential files ignored.

Machine-readable credential issuance and immediate rotation are substantial improvements over v0.0.1, but MCP clients and orchestrators must still treat entire token-returning responses as secrets and implement redaction before logging.

## Remaining product problems

These are Local Board product gaps observed or confirmed by the v0.0.2 experiment. The consumer `.pyc` mistake above is intentionally excluded because it was evaluator-project hygiene rather than package behavior.

| Priority | Problem | Experiment evidence | Recommended direction |
| --- | --- | --- | --- |
| P1 | Core interaction cost remains high. | The same mini-project needed 53 issue-addressed calls in both releases; v0.0.2 included 21 context reads and 14 transitions. | Add compound lifecycle operations or return next-action context/revision from every relevant mutation without weakening conflict safety. |
| P1 | Foreground server lifecycle is not automation-friendly. | Startup had no machine-readable readiness event; Ctrl-C printed a traceback and exited non-zero. | Handle `KeyboardInterrupt` cleanly and provide an explicit readiness/health contract; document a supported supervised process pattern. |
| P1 | Token-returning MCP responses are easy to leak through generic logging. | The evaluator's logger briefly persisted `create_actor` responses containing plaintext tokens to an ignored file before redaction. | Mark secret-bearing results in a machine-readable way or provide a credential-delivery flow that does not put plaintext tokens in ordinary MCP result logging paths. |
| P1 | Member permissions are broader than implementation work requires. | Members could not administer actors but still saw project, release, milestone, workflow, and label mutation tools. | Introduce capability-, project-, or issue-scoped authorization and filter `tools/list` accordingly. |
| P1 | Completion integrity is not universally enforced. | Terminal transitions still rely on agent discipline for acceptance criteria, checklist completion, reviewer requirements, and branch policy. | Add configurable server-side terminal gates and expose failed gates as structured blockers. |
| P2 | MCP domain errors require protocol-specific response inspection. | Conflict and forbidden results used HTTP 200 with `result.isError=true`; authentication alone used an HTTP error status. | Keep MCP-compliant structured errors, but strengthen client guidance/helpers so callers cannot mistake transport success for domain success. |

The first four problems are the highest-leverage candidates for the next dogfood iteration: they directly affect call volume, unattended operation, credential safety, and blast radius. Completion gates are equally important before Local Board is treated as a strong workflow-integrity boundary rather than a disciplined coordination aid.
