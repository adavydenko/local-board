# Dogfood baseline: v0.0.1

Date: 2026-08-19  
Artifact: `local-board==0.0.1` installed from the package index  
Consumer repository: `/workspace/local-board-dogfood`  
Scenario: Focus Board, as defined in the [evaluation protocol](README.md)

## Outcome

The experiment succeeded end to end. The coordinator created three dependency-ordered issues, implemented the application in three issue-keyed branches and commits, passed four standard-library tests, and moved all three issues to `done`. Local Board was usable as the operational record without direct SQLite access.

The result demonstrates a working single-machine issue lifecycle, not autonomous multi-agent readiness. Setup still depended on manual MCP client wiring and shell-created identities, and the published artifact did not install a root `AGENTS.md` discovery bridge.

## Notable observations

### Strengths

- The published artifact was installable without a source checkout.
- `init`, config validation/plan, actor creation, offline doctor, server startup, and online MCP doctor all worked.
- MCP exposed 38 tools and returned sufficient issue context for disciplined execution.
- Blocking dependencies changed from blocked to available when the prerequisite reached `done`.
- Checklist updates, comments, activity, and Git references formed a useful handoff record.

### Friction and risks

- The root agent-discovery bridge was absent after initialization.
- The coordinator needed a custom MCP caller because client configuration was not automatically installed into the running agent environment.
- Identity creation and token transfer were outside MCP, preventing a self-contained coordinator/subagent loop.
- Tool usage was verbose for a three-task project, especially revision reads and five workflow transitions per issue.
- Running the server as a durable background process was not portable in the experiment environment; a retained PTY was required.
- Acceptance criteria, checklist completion, reviewer requirements, and branch patterns were agent discipline rather than enforced completion invariants.

## Follow-up changes after the baseline

These improvements were made in the Local Board source tree after testing v0.0.1 and therefore do **not** change its score:

- safe root `AGENTS.md` bridge creation and doctor discovery diagnostics;
- documented lease and revision semantics;
- machine-readable `actor --json` output;
- MCP actor provisioning and token rotation;
- role-filtered MCP tool discovery.

They are hypotheses to validate against the released v0.0.2 artifact rather than assumed improvements.

## v0.0.2 rerun checklist

- Install with `python -m pip install local-board==0.0.2` in a new virtual environment.
- Confirm `local-board init` creates a discoverable root bridge without overwriting pre-existing instructions.
- Bootstrap the coordinator using JSON output without printing its token.
- Provision at least two subagents through MCP, verify their role-filtered `tools/list`, and rotate one token to prove the old credential is invalid.
- Repeat the same three Focus Board issues and dependency chain from a clean database.
- Record setup time, tool-call counts, workarounds, terminal issue state, test result, and server lifecycle behavior.
- Score all ten dimensions independently before reading this baseline total, then compare deltas and confidence.
